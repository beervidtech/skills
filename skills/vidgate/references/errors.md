# 错误码 × 退出码 × 处置动作

判成败永远以 envelope `code` 为准（HTTP 200 也可能是官方业务失败）。CLI 把 code 映射成语义化退出码。

| code | HTTP | 退出码 | 含义 | AI 处置动作 |
|---|---|---|---|---|
| 0 | 200 | 0 | 成功 | 正常继续 |
| 1001 | 401 | 2 | token 缺失/无效/已撤销 | 引导用户重新创建 token 并 login |
| 1002 | 403 | 2 | 用户被禁用 | 让用户联系管理员 |
| 1003 | 403 | 2 | 套餐过期（写操作被拒） | 提示续费；只读接口不受影响 |
| 1004 | 403 | 3 | 坐席额度不足 | 让用户联系管理员加坐席 |
| 1005 | 404 | 3 | 资源不存在或不属于你 | 核对 id 与账号归属；坐席 ID 口径别混（businessId vs creatorUserOpenId） |
| 1006 | 409 | 3 | 该账号已绑定在其他坐席 | 追加到原坐席即可（1 账号 = 1 坐席） |
| 1007 | 409 | 3 | 坐席未绑定 | 引导用户去控制台完成绑定 |
| 1008 | 409 | 3 | 同一坐席只能绑同一个 TikTok 账号 | 换坐席或换账号 |
| 2001 | 422 | 3 | 参数/文件校验失败 | 按 message 修正参数 |
| 2002 | 429 | 4 | 限流（60 次/分/token）或 TTS 预审配额耗尽 | 限流 CLI 已自动退避（Retry-After）；预审配额次日恢复 |
| 2005 | 422 | 3 | TT 视频 URL 已过期（7 天） | 重新上传后重试发布 |
| 3001 | 502 | 5 | TikTok 官方接口返回的错误 | 读 message（含官方原因）向用户如实解释；内容类违规 → 改素材重传 |
| 3002 | 504 | 5 | 官方接口超时 | 稍后重试 |
| 5000 | 500 | 6 | 内部错误 | 让用户联系管理员 |

## 本地错误（退出码 1，未发请求）

缺必填参数 / 文件不存在 / 文件超限 / 配置损坏等。读 stderr 提示修正即可。

## --wait 的退出码

| 场景 | 退出码 |
|---|---|
| publish_complete / 预审 passed | 0 |
| publish_failed / beervid_error / 预审 failed | 3（业务失败；读 failReason/beervid.reason 或预审 issues 解释） |
| 等待超时（默认 10min） | 1（stderr 说明最后状态；可再查 status） |

## 排错顺序

1. 退出码定位类别 → 2. 读 envelope `message` → 3. 涉及归属（1005）先 `seats list` 核对账号 ID → 4. 官方错误（3001）把 message 里的官方原因如实转告用户，不要自行编造原因。
